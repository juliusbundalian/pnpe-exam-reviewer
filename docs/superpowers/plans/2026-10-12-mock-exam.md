# Mock Exam, Results and History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an authenticated learner complete a durable 150-question timed practice exam, see a correct local result once, and revisit completed history while synchronization retries.

**Architecture:** Keep exam selection and scoring as pure domain functions. A dedicated SQLite repository owns complete preflight activation, answer/flag/cursor mutations, terminal result creation and outbox insertion in serialized transactions; an exam service coordinates the existing authenticated content repository and clock. Separate exam cloud paths and rules synchronize completed summaries without making cloud availability a prerequisite for local results. Routes reuse the app's auth, configuration, question rendering, theme and protected-navigation boundaries.

**Tech Stack:** TypeScript 6, Expo 57 / React Native 0.86, Expo Router, `expo-sqlite`, React Native Firebase Auth/Firestore, Zod 4, Jest and Firebase Rules emulator.

**Spec:** [Approved Mock Exam design](../specs/2026-10-11-mock-exam-design.md), approved by the owner in this session after the committed draft `5b02347`.

**Status:** Plan drafted for owner review; no Mock Exam implementation has begun.

## Global Constraints

- Preserve the approved 529-question bank, its live revision-2 catalog and all existing Reviewer/bookmark records. No editorial restamping or reimport.
- Default exam configuration is 150 questions, 180 minutes, app practice threshold 75%, category quotas 35/40/25/50. `communicationSkills` displays as Verbal Reasoning and `criticalThinking` as Logical Reasoning for exam presentation only.
- Start requires authenticated explicit action and a fully validated, durably stored set of selected question/stimulus/asset snapshots. Failure before commit creates no active deadline.
- Keep Home public and fast: do not open exam SQLite or download exam bodies during public bootstrap. Do not mutate existing Reviewer state when an exam starts.
- Use the current owner UID/device/epoch guard, exact choice IDs and frozen order. No answer/correctness/explanation reveal until terminal finalization.
- One active exam per account/device; repeated Start resolves it. Backgrounding and force-close do not pause the persisted deadline. Local finalization is idempotent and independent of upload success.
- Preserve the current isolated Android acceptance lifetime; do not run the resetting emulator suite against Firestore 8180 or clear the preserved AVD. Use a separate fresh emulator lifetime for destructive tests.
- Create an isolated Mock Exam implementation worktree from the reviewed feature commit; preserve the current Reviewer worktree and its ignored native evidence.
- No merge, push, production Remote Config/Firestore write, deployment or store upload in this plan.

## Review Focus

1. A selected shared-passage question whose neighbor is not selected must still retain its complete stimulus and exact choice mapping. Pin with `selects_shared_stimulus_without_neighbor` in Task 1 and `preflight_freezes_context` in Task 5.
2. A corrupted or missing question near the end of 150 must leave no active attempt/deadline and preserve a previous active attempt. Pin with `activation_rolls_back_on_last_question_failure` in Task 4 and `preflight_fetch_failure_has_no_attempt` in Task 5.
3. A delayed answer write racing expiry must never appear in the terminal score. Pin with `late_answer_rejected_inside_transaction` in Task 4 and `expiry_wins_open_confirmation` in Task 2.
4. A same UID on another device, or a different UID on the same device, must not see an active attempt or another owner's result. Pin with `exam_owner_device_isolation` in Task 4 and `remote_history_owner_only` in Task 6.
5. A retry after local finalization/cloud acknowledgement must not duplicate history or progress. Pin with `terminal_retry_is_idempotent` in Task 4 and `sync_retry_deduplicates_attempt` in Task 6.
